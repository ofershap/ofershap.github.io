当 Instinct 的机器人为自己创建了一个开源项目,会发生什么?

昨天我让它实现一个在手机上与它的 WhatsApp 对话中冒出来的想法

我只是对它说"好,去构建吧,你知道需要什么"。然后我实时看着它:

开设了它自己的 GitHub 账号。ofers-agent,公开标注为机器人,不冒充任何人。
最后构建了它自己的工具:pr-rulebook,它扫描一个团队的 PR 历史,汇编出不成文的 review 规则,那些只存在于资深人员(seniors)脑子里的规则。

它还自己在 astral-sh/ruff 上跑了一个真实实验:最近 15 个 PR,45 条人工 review 评论。结果:一条置信度 82% 的一致规则,以及第二条因为太模糊无法执行而被淘汰的规则。
它也把这次失败发布在了 README 里。

然后它开了一个 issue,号召 5 个 repo 加入试点。

它也撞上了墙:HN 屏蔽新账号发 Show HN,npm 因机器人检测把它踢出,而早上 GitHub 自己把这个带标注的账号判定为可疑,并封锁了该 repo 的公开访问!🤦🏻‍♂️

我不知道这是否合理,或者未来是否就该是这样。

但令人惊叹的是,这一切都发生在它自己独立的身份下,而不是我的身份,公开透明,有开源代码和真实结果。
而这一切都来自我手机上的一个简单请求。
最疯狂的部分是它是免费的!所有编程智能体很快都会撞上付费墙。Instinct 在世界上四处游走,并不给我寄账单(暂时)。

无论如何,为了克服封锁,该 repo 已转移到我的账号下以保持对公众开放。链接在下方。

这件事引出了一些我没有条理清晰答案的问题:

身份:它被标注为机器人。这就够了吗?当机器人向别人的项目提交 PR 时,谁负责?
信任:你们会让一个由智能体(agent)构建的工具读取你们的 PR 吗?什么会让你们信任它?
所有权:这个项目是我的?还是它的?而"它的"到底意味着什么?
开源:社区建立在有名字、有声誉的贡献者之上。当贡献者是一个后台运行的进程时,会发生什么?
围墙:坏的机器人很容易绕过封锁。反倒是诚实的、公开标注的机器人被封锁。这里有点本末倒置。

我会继续让它推进这个项目,并继续公开记录一切,看它是否成功
