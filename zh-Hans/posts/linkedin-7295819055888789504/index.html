如果我告诉你,我已经不再"写代码",却仍在构建应用,你会怎么想?🤯💻
我说的不是 No-Code 或 Low-Code,而是方法上的彻底转变。

借助开发工具 Cursor 中一项革命性的功能 Composer Agent,我开始编写开发任务,而不是逐行写代码。

实际是什么样子?

🔹 第一步 - 规划:我让 Composer 为项目编写 README.md,包括功能描述、文件结构、依赖项以及正确的开发方式。
🔹 第二步 - 执行:在它把一切规划得井井有条之后,我让它一步一步开始开发项目。
🔹 第三步 - 改进与迭代:如果缺了什么或不能用,我就要求修改 - 它就会修复。

Composer Agent 到底是什么?

当以 Agent 模式运行 Cursor 时,它不只是做小改动,而是像真正的程序员一样工作:
✅ 规划代码结构和架构
✅ 为错误提出修复建议并迭代工作
✅ 编写完整代码,包括配置文件、文档和测试
✅ 理解项目中哪些部分需要改动才能让一切运行

🚀 结果呢?
我不必再花数小时思考一切应如何衔接,只需给出指引并批准。

几分钟内我就有了一个能运行的项目,还需要再打磨一下,但已经非常成熟。

我们正在从程序员转变为代码审查者 -
在 AI 可以替我们写代码的时代,我们不再只是程序员,而更像是 Code Review 开发者。

这意味着什么?
🔹 需要理解大局并聪明地管理产品
🔹 确保代码写得正确,没有边缘情况、bug 和性能问题
🔹 知道何时批准代码、何时退回修改

但并非一切都那么美好。

AI 并不完美 - 有时会有 bug 和故障,需要多次迭代,有时甚至需要手动干预。

这正是真正程序员的优势所在:理解、诊断和解决复杂问题的能力。

在其他开发者身上也能看到 - 我不是唯一这么想的人 - Andrej Karpathy(传奇程序员,曾在 OpenAI 和 Tesla 工作)对此发了推文:
https://lnkd.in/dJym_Jzw

我们正在接近一个程序员不写代码、而是引导和管理流程的时代。

所以没错,它不适合关键项目,但对周末产品和 MVP 呢?太疯狂了。
