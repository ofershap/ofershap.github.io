一位朋友联系我,说他把 Cursor 升级到了 Pro 订阅,一天之后就已经用掉了订阅额度的 13%。于是我坐下来,为他也为你们写了下面这份指南:

* 如何节省 AI 开发成本(并节省 token) *

以下是根据我的经验可能对你们有帮助的一些小技巧,适用于 Cursor 和 Claude Code:

无论你是自掏腰包还是在组织中工作,采用这项技术之后,最先让你担心的就是成本意识。

如果你使用 Cursor -- 它自己会替你做很多工作,但仍有几件事是你可以自己做的:

- 尽量在每个新话题开始时开启一个新对话。如果现有对话的内容对你很重要,但又想减小上下文(context)的大小(这会影响 token 成本),那么在开启新对话之后,可以通过 @past 并选择那个对话,让它读取对话历史。

- 昂贵的模型更好,但自然……也更贵。
我用来节省成本的方法之一,是要求模型在更便宜的模型上运行次级智能体并对它们进行监督。(我甚至有一条这样的 rule)。
Spawn subagents and use composer-2 for the work it can do, and supervise it
有时(在大任务中)我会补充 - then critic it and run subagent to fix
这样我既获得了高速度(因为它可以并行运行),也获得了经济且合理的任务管理,甚至在我还没看代码之前就已经修复了代码

- 为任务选择模型是一块需要锻炼的肌肉。有两个我非常喜欢的键盘快捷键,它们彼此相邻。在键盘右侧 shift 键旁边有问号和末尾的"ץ"(词尾 tsadi,一个希伯来字母),所以在英文中,它们各自与 cmd 一起可以切换二者之一 -- 模型,或模式(plan、agent、ask)
我给自己选定了三个模型并一直在它们之间切换:composer-2、sonnet 4.6、opus 4.6。只要任务不复杂,很多任务我都用 Composer。对于需要更复杂思考的任务,或者做 Debug 时,我会换成更聪明的模型。
我不使用 Auto,我不知道那里发生了什么,而控制执行我任务的模型对我来说很重要。

也许值得了解的一件事:如果你在一个组织中工作,并且使用 enterprise 账户,那里有"一条被子"让所有人去拉扯,需要监控成本,我发布了一个开源项目,可以追踪、监控并就公司的支出获取提醒:https://lnkd.in/djZRK5ZP

那 Claude Code 呢?
首先我建议安装 claude code statusline,让它显示当前正在使用多少上下文,当你看到它膨胀时,可以开启一个新对话,或调用 /compact,还可以用一句话附上哪些重要需要保留、哪些可以舍弃(或者干脆让它自己决定)

此外,还有一些 skills 和库也能提供很大帮助:

Artik(希伯来语:ארטיק):https://lnkd.in/eXKPNNvV
一个节省 token 的代理(proxy),主要配合 Claude Code 使用(Cursor 已经自己处理了这一点)

"史前人类"(希伯来语:האדם הקדמות):https://lnkd.in/eqrJanMQ
把回答和内容的长度压缩成基本的"山顶洞人"语言,节省在对话中累积的文本量(= token)。代价是回答和解释会变少。

总结一下,
我们已经度过了技术采用阶段,升了一个年级,进入最优工作和尝试节省成本的阶段。新的游乐场迫使我们意识到成本,因为我们做的每个操作都要花钱,就像开车不能一整天都把油门踩到底、烧光整箱油一样,在这里需要管理"弹药经济"并优化我们的使用

你们还知道其他方法吗?很想听听!
