# 在用 Cursor 吗?给你一个黄金技巧:

在用 Cursor 吗?给你一个黄金技巧:
当我们通过 CLI 运行命令时,会出现错误。有时它们会抛到屏幕上,有时则藏在长长的日志行里。 

但当我们使用 Cursor 或其他替我们运行代码的智能体时,会发生什么?

这里出现了一个缺口。智能体"看不到"我们看到的东西。它无法实时监听日志,无法跟随 tail,也不会自动响应 Watch Mode。

这不是 bug -- 只是它的工作方式本来就不包括这些。如果它执行这样的调用,就会"卡住"并等到调用结束。

那么怎样才能确保自动运行不会破坏什么呢?
而且,不,答案不是为 CLI 做一个 MCP 😄 

我找到的办法很简单:
我把我的 npm 命令接好,让它把日志写入一个文件(在我这里是写进 logs/ 文件夹,因为项目里有不止一个环境),这个文件夹当然已加入 gitignore。 
我用 Tee 命令(类似更为人所知的 Tail)来写日志。

此外,我添加了一条 Cursor Rule,要求它在写完代码或排查故障时检查这些文件。

这样一来,在运行结束时,会主动检查这些文件,以发现漏网的异常、警告或错误。

没有 MCP 的复杂性,没有外部工具,只是把日志记录到文件。
有时,智能体看不到的东西 -- 一个日志文件却能说出来。
