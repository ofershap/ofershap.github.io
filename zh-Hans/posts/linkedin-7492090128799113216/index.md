我希望我的团队里有更多的"奥菲尔"。不是因为他是最快的开发者,而是因为一种在我看来已成为 AI 时代员工最重要的特质。你们认为,在如今的后 AI(POST AI)时代,员工最重要的特质是什么? 
我认为答案已经收窄为一件事:跳出框框思考。

我是在与 Ofir Cohen 的一次走廊谈话之后得出这个见解的,他用自己构建的智能体(agent)给了我惊喜,它能自动执行我们手动做的一系列操作。 
我这样一描述,听起来很平常,对吧? 
毕竟这大体上就是现在大家都在做的事

其实没那么平常 -- 看着大家已经习以为常的东西,去问为什么要这样做;识别出别人都没注意到的细节;不断质疑基本假设;然后还要懂得把这个想法接入系统,让它真正运转起来。

创造力、批判性思维和深厚技术理解的这种结合,在我看来是 AI 时代开发者最重要的能力。 

所谓的 continuous challenging yourself

想听听我们实际做了什么吗?
我原以为我们已经为改善开发者体验(Developer Experience)做了相当多的自动化,技能(skills)和命令(commands)已经自动化了诸如开 PR、自我评审(self review)、修复来自 master 的冲突、处理 review 评论并修复(或建议修复)等事情,在我看来,我们在日常流程的自动化方面已经达到了很高的优化程度。

然后牛人奥菲尔来了,又往前迈了一步 -- 与其让我们在回到某项任务工作时去运行这些命令,他在 Claude Code 里搭建了一个 Routine,每天多次遍历所有打开的 PR,并执行一些我以为自己已经自动化、但其实仍在手动运行的操作 -- 如果 CI 失败,它会修复;如果有评论,它会逐条处理并附上建议的解决方案交给我;如果与 master 有冲突,它会做 rebase 并修复合并冲突(merge conflicts);简而言之,一个小跟班(minion),确保我打开的 PR 始终保持最新,并把它尽可能嚼烂、准备好地交到我手上。

可以称之为对 Loop engineering 这一概念的聪明实现

而这只是本周团队中的一个小例子。这里每天都有整个团队想出的巧妙办法,多到篇幅都容纳不下。 

如果整个团队都由跳出框框思考的人组成,而且系统鼓励这样做,那么在如今这个把想法转化为成果已经毫不费力(no brainer)的时期,能够达到的发展速度是指数级的,尤其是当你驾驭自主 AI 智能体来推动系统向前时。

毕竟,我们处在一个新时代,独自一人、没有帮助地主导开发已失去意义。我们与精通代码的人工智能大脑并肩工作,这种编码的委托造就了人与机器之间的结对编程(pair programming),并给我们留下了非常特定的特质,更多是主导上下文和口述创作。 

在我看来,会背 leet code 答案的开发者与会问智能体答案的开发者已经没有区别了。如果你在面试中问(或被问)的问题一个 prompt 就能解决,那这个问题就是多余的。无论是代码问题、架构问题,还是组织中其他职位,比如管理或运营职位。

我们确实处于过渡期,所以我猜仍有公司继续问同样的问题、用与 AI 时代之前相同的方法面试,因为这个时代才刚刚开始,但这是暂时的。

对于跳出框框思考的创意人士来说,这是个好时期
也许我们都是这样的人,只是现在才形成了让我们的创造力得以表达的沃土?
