最近大家常听到的 MCP -- 它到底是什么意思?!
要把它解释清楚:想想互联网是怎么开始的:
必须发明一种共同语言,这样一台计算机才能与远程服务器对话。这就是 HTTP 的发明。今天这一切对我们是透明的,我们使用浏览器软件访问网站,却忘了它们建立在一套全球公认的基础设施(一种协议)之上,用于传输通信和信息,使这些网站得以出现在我们的电脑上。

同样的事情现在正发生在 AI 身上。
只不过现在需要懂得"说话"的不是你 -- 而是人工智能。
这并不简单,GPT 不知道什么是"发送邮件"或"预约",它需要有人向它解释可以做什么、用什么语言、什么格式,以及点击之后会发生什么。

这就是 MCP(全称 model context protocol)所做的事 -
这是一个公认的协议,所有公司正在慢慢采用它,它正成为我们教 AI 如何与系统、服务、按钮、菜单以及一切对话的方式。

怎么做到?这完全不简单 -- 它需要把我们的 API 翻译成机器能理解的语言。网络上每一个想对人工智能开放的服务,都需要为其增加这样的接入(一个 mcp 服务器)。

我们从产品人员为开发者撰写文档的状态,转变为如今开发者为人工智能撰写文档的状态。

这感觉有些荒诞,但这就是我们现在所处的阶段。为 AI 梳理出它可以使用的所有服务,以及它访问各种系统的方式,使它能够"一条命令"为我们执行操作。

就像我们需要协议才能浏览互联网、查看网站,于是诞生了今天对我们来说透明的 HTTP 这类概念一样,如今,尽管难以想象,必须发明一种新协议,让人工智能能够自行访问数字服务。

必须有人真正坐下来梳理我们至今使用的技术通信("手动"的那种,开发者看得懂的那种)-- 如 API、按钮、表单等 -- 并把它转化为人工智能能够使用的语言。

这是一门把技术命令转换为机器命令语言的艺术,它需要:
- 解释这个系统究竟能做什么
- 哪些操作在 API 或 UI 中暴露出来
- 如何访问它们(以及如何安全地访问!)
并用清晰的英语写明 AI 应该怎么做才能使用它们

例如:
如果有一个发送邮件的按钮 -- 你需要这样告诉人工智能:
"要发送邮件,请使用 send_email 操作。指定收件人、主题和内容。格式应为如此这般的 JSON。"

这不完全是编程,也不是普通文档 -- 这是一种新语言,在会思考的计算机与执行的计算机之间进行中介。
这就是 MCP。

这就是我们现在所处的阶段,谁不能及时理解这一点 -- 就会被挤出游戏。
