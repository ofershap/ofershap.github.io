עופר שפירא

בונה מערכות AI. מוביל צוותים שעובדים איתן.

אני עופר שפירא, מוביל צוות AI Engineering ב-Elementor, מפתח ויזם לשעבר. אני עובד בחיבור שבין קוד, מוצר ואנשים: בונה מערכות מבוססות AI, מוביל צוותי הנדסה, ובודק איך סוכנים משנים את העבודה בפועל.

הבלוג הזה הוא הבית של הכתיבה המקצועית שלי. כאן אני מתעד מה בנינו, מה ניסינו, איפה זה נכשל ומה שינינו בעקבות זה. הוא מרכז את הפוסטים שלי מלינקדאין לצד מדריכים ומאמרים, כדי שהידע יישאר נגיש מעבר לפיד.

במה אני מתמקד

  • AI בתוך תהליך הפיתוח: עבודה עם סוכני קוד, הגדרת משימות, Code Review ובדיקת התוצר.
  • סוכנים שמתחברים למערכות אמיתיות: כלים, MCP, אוטומציה וניהול הקשר.
  • הובלת צוותי הנדסה: אימוץ AI בצוות, אחריות על החלטות והמעבר מכתיבת קוד לבדיקתו.
  • כלי פיתוח וקוד פתוח: כלים קטנים שמקצרים עבודה חוזרת ומאפשרים לבדוק רעיון בפועל.

הרקע שלי

יש לי יותר מ-15 שנות ניסיון בפיתוח ובהובלת צוותים. לפני Elementor עבדתי ב-monday.com, הובלתי צוותי פיתוח ב-Via וב-Novidea, וייסדתי את DSM Tool, חברת SaaS שנרכשה בהמשך בידי AutoDS. אני בעל תואר ראשון במדעי המחשב ותואר MBA, ובוגר יחידה 8200 כמפתח תוכנה.

הניסיון הזה משפיע על השאלות שאני שואל: האם המערכת פותרת בעיה אמיתית, איך היא משתלבת בעבודה של הצוות, ואיך יודעים שהיא עובדת גם אחרי הדמו.

פרויקטים פתוחים

  • real-browser-mcp - חיבור סוכנים לדפדפן Chrome אמיתי עם ההתחברויות הקיימות.
  • agents-control-tower - הפעלה ומעקב אחר סוכני Cursor מהטרמינל.
  • cursor-usage-tracker - מעקב שימוש ועלות של Cursor בצוות.

מאיפה להתחיל לקרוא

  • איך מקלים על Code Review בעזרת PR Description - ארבעה חלקים שעוזרים להבין שינוי לפני קריאת הקוד.
  • איך מסנכרנים משתני סביבה בצוות - מעבר מתיאום ידני לפעולה שמתרחשת בזמן הרצה.
  • מי דואג שקבצי הקונטקסט נשארים נכונים - ההבדל בין זיהוי קישור שבור לבין בעיה שצריך לתקן.
