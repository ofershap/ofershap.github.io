This week we finished delivering a 5-session Cursor workshop to all of R&D, with the goal of getting to know Cursor as a work tool that fits in across the entire development cycle.

Throughout the sessions we went together through every stage of the process - from planning and specification, through writing code and tests, to code reviews and delivery. In every session we connected Cursor to the participants' real work: processes, tactics, and tasks drawn from that session's topic.

The focus wasn't only on the tool itself, but on practice: how to use it to speed up development, get to know its capabilities, reduce code errors, and improve decision making.
More than anything the goal was to show that it's a powerful, revolutionary and above all accessible tool, so that every one of the developers can start working with it.

And yes, also to talk about the new challenges it poses, and the new skill that has to be learned in order to find the balance between letting it write the code (which happens at an unbelievable speed) and the need to keep looking at the code that was written and dictate to it what to fix and how to work (which remains slow and challenging, and is still required of developers).

We've entered a new era in which we, as the holders of the full picture (the context), have gone from manually writing code to dictating, planning and also reviewing code. It's an event you need to experience, practice, digest, and get through in order to complete the process of moving from developer to Context Engineer.

In the end, a workshop like this is less about what Cursor knows how to do, and more about what it takes to adopt an LLM-based development tool - as part of the progress of technology and the AI revolution, and not just as another technological add-on. In order to stay relevant.

It's a process that can't be skipped.
