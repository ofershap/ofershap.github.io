כותרת: מתי הוראות חוזרות לסוכן הופכות ל-Skill?

**תשובה קצרה:** עובדה על הפרויקט שייכת לקובץ הכללים. תהליך שחוזר על עצמו שייך ל-Skill. ההבדל המעשי: קובץ הכללים נטען תמיד ועולה בכל שיחה, ו-Skill נטען רק כשצריכים אותו. כלל אצבע: אם הדבקתם את אותה הוראה שלוש פעמים, הגיע הזמן לתת לה בית.

### קובץ כללים הוא עובדות, Skill הוא תהליך

בתיעוד של Claude Code ההפרדה מפורשת: יוצרים Skill כשמדביקים שוב ושוב את אותן ההוראות, אותה רשימת בדיקות או אותו תהליך רב-שלבי, או כשחלק בקובץ הכללים גדל לתהליך במקום עובדה. "אנחנו עובדים עם TypeScript strict" היא עובדה. "ככה פותחים PR אצלנו, שלב אחר שלב" הוא תהליך.

המחשה: חוק שאומר "כל PR כולל תיאור של ההחלטה" נשאר בקובץ הכללים. תהליך של שישה שלבים לבדיקת מיגרציה לפני מיזוג הופך ל-Skill.

### למה העלות של הטענה קבועה משנה

כל מה שיושב בקובץ הכללים נטען לכל שיחה, גם כשלא רלוונטי. Skill נטען רק כשהסוכן מזהה שהוא נחוץ או כשקוראים לו בשם. בצוות זה אומר שאפשר לתחזק ספרייה שלמה של תהליכים בלי לנפח כל שיחה. התיעוד קורא לזה שהגוף של ה-Skill עולה כמעט כלום עד שמשתמשים בו.

### איך מתחילים בפועל

שלב ראשון, פותחים את ההיסטוריה של השיחות ומחפשים הוראה שהדבקתם פעמיים או יותר. שלב שני, כותבים אותה פעם אחת כ-SKILL.md עם שם קצר ותיאור מתי להשתמש בו. שלב שלישי, מנסים על משימה אמיתית ומתקנים את הניסוח לפי מה שהסוכן עשה בפועל, לא לפי מה שרציתם שהוא יעשה.

בעבודה שלי עם הסוכן על ה-open source שלו, הבנתי שהשם והתיאור הם מה שהסוכן קורא כדי להחליט אם ה-Skill רלוונטי. תיאור מעורפל אומר Skill שלא ייפתח אף פעם, או ייפתח בדיוק ברגע הלא נכון.

### בדיקה שה-Skill עובד

אחרי שכתבתם, מריצים את התהליך על מקרה אמיתי ובודקים שלושה דברים: הסוכן פתח את ה-Skill בזמן, עקב אחרי השלבים בסדר, והתוצר זהה למה שהייתם עושים ידנית. אם אחד משלושתם נפל, מתקנים את ה-SKILL.md ולא את התוצר. תיקון התוצר מסתיר את הבעיה לפעם הבאה.

## מהניסיון שלי

בפוסט שלי סיפרתי שהבוט שלי פתח לעצמו פרויקט open source ואפילו פרסם ב-README גם את הכישלון שלו. אחרי שבועות של עבודה כזאת שמתי לב שאני מדביק לו שוב ושוב את אותן ההוראות. בתיעוד של Claude Code על Skills יש תשובה מדויקת מתי ההוראות האלה צריכות להפוך לקובץ, ומתי הן צריכות להפוך ל-Skill.

## בקצרה

עובדה על הפרויקט שייכת לקובץ הכללים. תהליך שחוזר על עצמו שייך ל-Skill. ההבדל המעשי: קובץ הכללים נטען תמיד ועולה בכל שיחה, ו-Skill נטען רק כשצריכים אותו. כלל אצבע: אם הדבקתם את אותה הוראה שלוש פעמים, הגיע הזמן לתת לה בית.



## שאלות נפוצות

### מה ההבדל בין Skill לפרומפט שמורים בקובץ?

Skill נושא שם, תיאור מתי להשתמש בו, וקבצי עזר, והסוכן מחליט לטעון אותו כשרלוונטי. פרומפט שמור עדיין דורש שתזכרו להדביק אותו.

### כמה Skills נורמלי להחזיק?

כמה שיש לכם תהליכים חוזרים אמיתיים. הסיכון הוא לא כמות אלא תיאורים מעורפלים, שגורמים לסוכן לבחור Skill לא נכון.

### ומה עם קובץ הכללים, נשאר רלוונטי?

כן, לעובדות יציבות על הפרויקט: שפה, קונבנציות, אילוצים. כל מה שהוא תהליך עם שלבים עובר ל-Skill.
